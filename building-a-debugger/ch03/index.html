第 3 章导读 · 附加到进程

 2026.10.5  2026.10.6  1819  4 分钟
一句话概括：调试器终于"活"了——本章用 fork/exec 加 ptrace 让 sdb 能启动或附加到真实进程，并用 waitpid 感知其停止原因，随后把代码重构为 sdb::process 库加命令行驱动。

本章在全书中的位置

这是全书第一次写"真正能跑"的调试器代码，第 2 章铺垫的 ptrace、信号、程序加载在此落地。本章建立的 sdb::process 抽象和 stop_reason 机制是后续一切功能的载体：断点（第 7 章）表现为"等进程因信号停下"，栈回溯（第 16 章）要拿进程寄存器，都要经过这一章定义的接口。作者还埋了一个伏笔：launch 里的错误处理有缺陷，第 4 章才修。

逐节要点（用自己的话讲）

1. fork 与 exec

Linux 没有凭空创建进程的机制，只有"复制自己再换程序"：fork 把进程一分为二，子进程里返回 0、父进程拿到子进程 PID；随后子进程用 exec 家族 syscall 把自己替换成目标程序。所有进程由此构成一棵以 PID 1（init/systemd）为根的家族树，可用 ps ax --forest 观察。理解"先复制后替换"是理解"启动并调试"的关键。

2. ptrace：一个又老又全能的接口

ptrace 诞生于 1975 年的 V6 Unix，API 风格和现代设计理念完全不搭：一个函数配一个 request 参数能干几十件事。被调试的进程术语叫 inferior。作者强调了本书最实用的工程忠告之一：ptrace 出错返回 -1 并设置 errno，返回值含义还随 request 变化——务必检查返回值，否则你会花几小时追一个自己埋的 heisenbug。

3. 两条附加路径与 waitpid

调试器支持两种用法：sdb <程序名> 启动并调试，sdb -p <pid> 附加已有进程。前者走 fork → 子进程 PTRACE_TRACEME → execlp 的套路（被 trace 的进程 exec 时内核会让它自动停下）；后者直接 PTRACE_ATTACH（内核会给目标进程发 SIGSTOP）。两条路最后都要 waitpid 等待停止，用 WIFSTOPPED、WIFEXITED 等宏解读 wait 状态。作者还顺带提醒了 argv[1] == "-p" 比较的是指针不是内容的经典 C++ 坑。

4. 命令行界面与命令解析

交互层用 libedit（LLDB 也用它）拿到历史、搜索这些成熟能力；空行回车 = 重跑上一条命令。命令风格向 GDB/LLDB 看齐，且支持前缀匹配——输 c 就等于 continue。小细节：封装继续执行的函数不能叫 continue，那是 C++ 关键字，所以叫 resume。

5. 手动测试与 Yama 权限坑

用无限输出 y 的 yes 程序验证启动，用后台死循环加 PID 附加验证 attach。最大的坑在这：不少发行版默认开着 Yama LSM，非子进程不让 attach，会直接报错。解法有两个：临时把 /proc/sys/kernel/yama/ptrace_scope 设为 0，或者给 sdb 加 CAP_SYS_PTRACE 能力。WSL2 环境下这一节务必亲手过一遍。

6. 重构为 sdb::process 库

quick-and-dirty 版跑通后，本章把 ptrace 调用全部下沉进库里的 sdb::process 类型：静态工厂 launch/attach 创建对象，禁用默认构造和拷贝（进程是独占资源，拷贝没有意义），用 terminate_on_end_ 区分"自己启动的要负责杀掉"和"附加来的要还回去"。进程状态用 enum class 的 stopped/running/exited/terminated 表达。命令行驱动从此对 ptrace 一无所知。

7. 错误处理与对象生命周期

C++ 的错误处理有忽略/异常/错误码/result 类型几派，LLDB 禁用异常所以自建 result，本书选了异常：sdb::error 继承 std::runtime_error，提供 send 和 send_errno 两个抛出点。析构函数里要detach 进程（PTRACE_DETACH 要求进程先停着，所以先 SIGSTOP 再 DETACH 再 SIGCONT），自己启动的就 SIGKILL 收尾；析构里绝不能抛异常，错误只能忍。waitpid 的结果被解析成 stop_reason 结构体，命令行据此打印"因什么信号停下"。

结合你的背景给的建议

  • fork/exec、PID、信号这些你用 Frida 时都间接碰过——Frida 的 spawn/attach 恰好对应本章的 launch/attach 两条路径，ptrace 相当于你在 Linux 上做注入绕不开的底座。这章对你的"新知识"主要是 C++ 侧的接口设计。
  • C++ 经验一般的话，重点看三样：static 工厂 + 私有构造的资源类型写法、= delete 禁拷贝的惯用法、enum class。std::unique_ptr 的侧栏认真读一下，全书大量使用。
  • 动手前先确认环境：必须 Linux/WSL2，Windows 原生跑不了 ptrace。遇到 attach 被拒，先查 ptrace_scope，别怀疑自己代码。
  • 作者给的 top-down 写法（先假设函数存在再实现）值得照做；对照 GitHub 上 chapter-3 分支核查你的实现，尤其注意 launch 里子进程出错路径的问题——它就是第 4 章要修的伏笔。
  • libedit 在 WSL2 上装起来很顺（libedit-dev），不必换 readline。

与后续章节的衔接

下一章先修本章遗留的错误处理缺陷（子进程在 exec 前出错无法通知父进程），再用管道建立调试器与被调试进程的通信，把本章的手动测试变成自动化测试套件——这是全书能放心大改代码的安全网。之后第 5 章就会通过这个 process 抽象去读寄存器了。
