第 21 章导读 · 表达式求值

 2026.10.5  2026.10.6  2847  6 分钟
一句话概括：全书最后一个编码章——在调试器里实现"在活着的进程中替用户调一次函数"：解析函数调用、按 SYSV/Itanium ABI 摆好参数与返回值、借入口点断点当返回地址，从此 expr get_cat("Marshmallow") 真的能在被调试进程里跑起来。

本章在全书中的位置

前两章解决了"变量在哪、是什么"，本章解决调试器的圣杯之一：表达式求值。作者先泼冷水——GDB/LLDB 为了支持任意 C++ 表达式，本质上内嵌了一个 JIT 编译器，本书不打算这么干。于是范围被狠砍到"单次函数调用"：支持 feed(marshmallow)、marshmallow.have_birthday()、传字符串/整数/浮点/布尔字面量，支持重载；不支持赋值、算术表达式、嵌套调用、链式调用、隐式转换和默认实参。砍完之后工程量收敛到可实现，而核心机制与真实调试器一脉相承。这也是全书写码量最大的一章。

逐节要点（用自己的话讲）

1. 返回地址难题与入口点技巧

调函数要先回答"调完了回到哪"。用当前 PC 不行——用户可能调用正在执行的函数，内部断点会提前命中；把返回地址放栈上不行——栈通常不可执行，会段错误；现 mmap 一块可执行内存又鸡生蛋（调 mmap 本身就需要一次 inferior call）。作者的解法很巧：复用扫描共享库时打在程序入口点上的那个断点——它已经被命中过、不会再进，把入口地址当返回地址，白捡一个"调完通知我"的机制。

2. 名字查找扩展与 $N 历史

第 20 章的 resolve_indirect_name 被扩成"变量或函数二选一"：遇到 ( 就查函数，成员函数靠遍历变量类型 DIE 的子节点、用 DW_AT_object_pointer（this 指针对应的形参 DIE）筛出非静态成员函数。同时引入 $0、$1 编号引用历史求值结果，既可当实参也可当成员函数的对象——结果内存特意用 inferior_malloc 分配，保证整个调试会话存活。

3. 内置类型与参数解析

字面量参数没有 DIE 可依，于是 type 类被改成 std::variant<die, builtin_type>：整数按 8 字节（等价 long）、浮点按 8 字节（等价 double）、布尔/字符 1 字节、字符串传指针。parse_argument 逐类识别：字符串要先在进程里 malloc 再写入；数字含点按 double 解析；否则当变量名走既有查找链。collect_arguments 还要按 Itanium ABI 给成员函数补隐式 this——对象有地址就直接用，没有（比如在寄存器里）就压到栈上再取地址。

4. 简化版重载决议

不做编译器那套复杂得吓人的决议，只做"形参数量相等且逐个类型相等"的精确匹配，多于一处匹配报"歧义"。类型相等 operator== 也从简：内置类型比枚举；内置对 DWARF 按 DW_ATE 编码归约；DWARF 对 DWARF 则剥掉所有限定后比名字——const 重载因此分不出来，作者明说这实现"不准但够用"。照抄代码注意：die::parameter_types 开头的守卫条件印刷有误（应为 != 而非 !...==），原样抄进去早退分支永不触发。

5. 调用约定：本章的理论重心

SYSV ABI 按 8 字节的 "eightbyte" 给参数分类：INTEGER（通用寄存器）、SSE/SSEUP（xmm 低/高 8 字节）、X87/X87UP/COMPLEX_X87、MEMORY（走栈）、NO_CLASS。聚合类型最复杂：先看是否 NTFPOC（"对调用而言非平凡"——拷贝/移动构造或析构非平凡，或全部被 deleted；近似但不等于 C++ 的 trivially copyable），是则按隐形引用传指针；超过 16 字节或有未对齐字段（比如 #pragma pack）直接 MEMORY；否则逐成员递归分类、按合并规则（INTEGER 粘性、X87 系合并即 MEMORY 等）归并到所属 eightbyte。传参时 INTEGER 依次进 rdi/rsi/rdx/rcx/r8/r9，SSE 进 xmm0~7；栈参数从右往左压（为 varargs 服务），调用点栈需 16 字节对齐，可变参函数还要求 al 存用过的向量寄存器数。返回值对称：INTEGER 走 rax/rdx，SSE 走 xmm0/xmm1，long double 走 st0，MEMORY 类由调用方在 rdi 里传隐藏的返回槽指针。书里明确不做 __m128/__m256、__int128 和复数类型——GDB 对 complex long double 同样不支持。

6. 机器层与组装

process::inferior_call 是最底层：改 rip、栈顶写返回地址、恢复运行、等停后还原寄存器并交回快照。inferior_malloc 借道 libc 符号表找到 malloc，用同一套入口点机制替用户调它。中层是把分类算法落到代码：get_parameter_classes / classify_class_type / classify_class_field / merge_parameter_classes 几乎是规范条文的直译；is_non_trivial_for_calls 递归查成员、基类（DW_TAG_inheritance）、虚成员（DW_AT_virtuality）和未 defaulted 的拷贝/移动构造与析构——并提醒 GCC 在 DWARF 4 下常常不给 DW_AT_defaulted，会被当非平凡处理。成员函数定义可能藏在 DW_AT_specification / DW_AT_abstract_origin 的 DIE 链里（内联信息的产物），所以建了个"声明位置 → 定义"的索引递归解析。最后 evaluate_expression 把所有环节串起来：解析、收参、决议、摆参（setup_arguments，含引用参数物化、返回槽占 rdi、栈对齐）、调用、read_return_value 写回返回槽并登记为 $N；get_expression_result 取历史结果时会重读内存——$0 若被按引用传入改过，得取新值。

7. 测试

本书最后一个编码章不再写自动化测试，改为手工验证：测试程序准备了按寄存器/双寄存器/内存三种路径传参的 small / two_eightbyte / big 结构和一组 print_type 重载。会话演示了完整闭环：get_cat 返回 $0，$0.give_command 打印消息（字符串传参 OK），$0.increase_age 后 var read $0 看到年龄真的变了，各 print_type 重载按类型正确分发。跑通这一段，你就拥有了一个功能相当齐整的 x64 原生调试器。

结合你的背景给的建议

  • 这章对你其实是"旧知识新视角"：SYSV 调用约定、rdi 起始的整型寄存器序列、16 字节栈对齐、al 计数向量寄存器——写 x64 汇编和 Frida NativeFunction 时天天在用，只是第一次从"调用方就是调试器"的角度系统实现一遍。理论节可以快读，重点看 NTFPOC 与八字节合并这两个汇编层面看不出来的规则。
  • 现代 C++ 密度确实高，但集中在模式而非算法：variant<die, builtin_type> 建模"类型可能不在 DWARF 里"、结构化绑定、可变参数模板复用。不必纠结语法，抓住数据流：字符串 → typed_data → 分类 → 寄存器/栈布局。
  • 强烈建议对着测试目标动手跑：故意传一个 #pragma pack 的结构、一个带 std::string 成员的类，观察 NTFPOC 报错——比读十遍代码都有用。逆向视角看，这就是"手工构造一次函数调用帧"的教科书实现。
  • 留意作者的边界决策：入口点当返回地址、返回槽总是 malloc（哪怕寄存器返回）、不做 NTFPOC 按值传参——每一条都是工程妥协，也是扩展练习的现成题目。
  • 环境照旧 Linux/WSL2；入口点断点机制依赖此前共享库扫描章节的实现。

与后续章节的衔接

到这里编码部分完结：sdb 已是一个覆盖断点、单步、栈回溯、共享库、多线程、变量查看与函数调用的 x64 原生调试器。第 22 章是收官的"进阶主题"，列出值得继续深挖的方向。自测题七问几乎全是调用约定常识（两份 ABI 文档、第一个整型参数寄存器、varargs 特殊规则、X87 何时进寄存器、NTFPOC 含义、栈参数入栈顺序、栈对齐要求），可以当面试题自查。
